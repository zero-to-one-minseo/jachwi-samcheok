# 조립 사양서

2026-11-05 19:40 작성(메인). 앱을 부품으로 나눠 **이미 만든 우리 코드, 오픈소스, 새로 짤 연결 코드**로 조립하기 위한 사양이다. 부품마다 받는 것, 돌려주는 것, 합격 기준을 정한다. 기술 사실은 [기술_확인.md](기술_확인.md), 기능의 이유는 [설계_구현방법.md](설계_구현방법.md)와 [설계_시세현황판.md](설계_시세현황판.md)를 따른다. 진행은 [메인_현황판.md](메인_현황판.md)에 적는다.

## 0. 원칙

- **스택은 그대로다.** Python 3.12 + Streamlit 1.66.1, Community Cloud 배포. 직방·당근 같은 화면의 오픈소스는 대부분 React·Next.js라 그대로 끼울 수 없다. 오픈소스는 **Streamlit에서 쓰는 라이브러리·부품** 위주로 고른다.
- **라이선스:** MIT, BSD, Apache-2.0만 쓴다. GPL·AGPL은 쓰지 않는다. 라이선스가 없는 저장소는 코드를 가져오지 않고 아이디어만 참고한다. 쓴 것은 모두 `app/CREDITS.md`에 이름, 주소, 라이선스, 쓴 곳을 적고 발표에서 밝힌다.
- **대회 규칙:** 라이브러리를 쓰는 것은 괜찮다. 남의 앱 코드를 통째로 가져와 고쳐 쓰는 것은 20:00 멘토링에서 허용 여부를 묻고, 답을 듣기 전에는 하지 않는다.
- **새 패키지는 민서 허락을 받고 넣는다**(내려받기). requirements.txt에 판을 고정한다.
- **이미 동작하는 부품은 다시 만들지 않는다.** 계약서 점검(C1~C6)은 그대로 쓴다. 이번 조립의 중심은 지도 현황판(R4~R9)이다.

## 3. 지도 현황판 화면 사양 (R9)

### 배치

- **넓은 화면(노트북·발표):** 위에 요약 띠(R8)와 필터(R5)를 한 줄로 접어서 둔다. 아래는 2열이다. 왼쪽 약 60%는 지도(R4), 오른쪽 약 40%는 선택한 방 상세(R7)와 방 목록(R6)이다.
- **휴대폰(640px 이하):** 열이 위아래로 쌓인다(Streamlit 기본 동작). 순서는 요약 → 필터(접힘) → 지도(높이 약 350px) → 선택한 방 → 목록이다.

### 지도

- **처음 화면:** 학교 정문과 삼척 시내(남양동)가 함께 보이는 범위다. 중심과 확대 정도는 `생활권_중심.csv`로 정한다.
- **방 점:** 점 위나 옆에 **월 환산 가격(만 원)**을 숫자로 쓴다(직방 식). 가격이 없으면 '?'.
- **색:** 생활권 가운데 값보다 3만 원 넘게 싸면 초록, 3만 원 넘게 비싸면 주황, 그 사이면 회색이다. 색만으로 뜻을 전하지 않도록 상세 카드에 글자로도 쓴다.
- **양도 매물:** 테두리나 모양을 달리하고, 범례에 적는다.
- **겹침:** 같은 좌표에 방이 여러 개면 id로 정한 작은 고정 흩뜨림(같은 데이터면 늘 같은 자리)을 준다. 흩뜨림 반경은 좌표 정밀도(약 100m)를 넘지 않는다.
- **생활권 표시:** 생활권 중심에 이름 글자(후문, 정문, 교동택지, 당저동, 시내, 마달동)와 학교 표시를 둔다.
- **위치 안내:** 지도 아래에 고정 문구를 둔다. "점 위치는 길 단위로 뭉갠 대략 위치예요. 정확한 건물이 아니에요."

### 상호작용

| 사용자가 하면 | 앱이 한다 |
|---|---|
| 지도 점을 누름 | `st.session_state["room_selected_id"]`에 넣고, 오른쪽 맨 위에 그 방 상세(R7)를 보이고, 목록에서 그 방을 강조한다 |
| 목록에서 방을 누름 | 같은 상태를 바꾸고, 지도 중심을 그 방으로 옮긴다(다시 그릴 때 view state로) |
| 필터를 바꿈 | 지도 점, 목록, 요약이 함께 바뀐다. 선택한 방이 걸러지면 선택을 지운다 |
| 생활권 단추를 누름 | 지도를 그 생활권 중심으로 옮기고, 필터의 생활권도 그것으로 맞춘다 |
| 상세의 '계약 전에 계약서 점검하기' | selected_room을 넣고 계약서 페이지로 간다(지금 동작 그대로) |

### 넣지 않는 것

정확한 건물 좌표, 호수, 연락처, 에타 글 주소, 남의 매물 사진, 지도 위 개인 정보.

## 4. 계약서 페이지 (C1~C6)

지금 구현을 그대로 쓴다. 조립 단계에서 바꾸는 것은 두 가지뿐이다.

## 5. 데이터 사양

- **rooms.csv**(R1이 만든다, utf-8-sig): id, show, hide_reason, surveyed, source, posted, name, dong, area, kind, contract_type, deposit, monthly, monthly_low, monthly_high, prepaid_total, prepaid_months, orig_total, fee, fee_text, included, structure, size, size_m2, options, distance, memo, **lat, lon, geo_precision**.
  - 좌표는 소수 셋째 자리(약 100m)까지다.
  - geo_precision은 도로중심, 블록, 생활권중심 중 하나다.
  - 좌표가 없으면 생활권 중심 좌표를 넣고 geo_precision을 생활권중심으로 둔다.
- **좌표표.csv**(조사 세션이 만든다): id, name, dong, area, lat, lon, precision, method, note. R1은 **name과 dong이 같은 줄**로 합친다. id는 데이터를 다시 만들면 바뀔 수 있어서 키로 쓰지 않는다.
- **생활권_중심.csv**: area, lat, lon(후문, 정문, 교동택지, 당저동, 시내, 마달동, 학교).
- **baseline_molit.csv**: 국토부 실거래 CSV 그대로. R3가 읽는다.
- 팀 구글 시트는 내일 10:00에 CSV로 받아 `data/raw/`에 넣고 R1을 다시 돌린다.
