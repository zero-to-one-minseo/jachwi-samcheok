## 0. 먼저 읽을 것: 설계와 달라진 12가지

1. **Python은 3.12로 통일한다.** 로컬은 uv로 만든 3.12 가상환경, Community Cloud는 첫 배포 때 3.12를 직접 고른다. 배포한 뒤에는 바꿀 수 없다. 이 Mac의 `python3`(3.15)와 `/usr/bin/python3`(3.9)는 쓰지 않는다.
2. **anthropic 최신 판은 2.5.0이다(1.x가 아니다).** SDK 1.0부터 `temperature`·`top_p`·`top_k` 인자가 없어져서, 넘기면 요청을 보내기도 전에 TypeError로 멈춘다.
3. **effort는 `output_config` 안에 넣는다.** thinking 안이 아니고, effort라는 최상위 인자도 없다. `thinking`은 아예 보내지 않는다.
4. **구조화 출력은 `parse` 대신 `create`로 받고 `stop_reason`부터 본다.** `parse`는 ValidationError가 나면 응답 객체를 주지 않아 잘림과 거절을 구분하지 못한다(3장).
5. **시간 초과도 SDK가 자동으로 다시 보낸다.** 그래서 `max_retries=0`으로 두고, 앱 코드가 정한 오류만 1회 다시 보낸다.
6. **사용 한도 오류는 하나가 아니다.** 우리가 콘솔에서 건 한도는 400, 등급 월 상한은 429다. 둘 다 다시 보내지 않는다.
7. **Community Cloud는 오류 표시 설정을 강제로 덮어쓴다.** config.toml로는 끌 수 없다. 앱 본문 전체를 try/except로 감싸는 것이 주 대책이다.
8. **Streamlit 업로더가 거절한 파일(형식·크기)은 Python까지 오지 않는다.** HEIC·크기 안내는 올리기 칸의 label·help와 바로 아래 고정 글로 늘 보여 준다.
9. **분석 중에 값을 가진 위젯은 숨기지 말고 `disabled`로 막는다.** 숨기면 올린 파일이 사라진다.
10. **저장본 화면은 '키 없이'는 뜨지만 '인터넷 없이'는 로컬 실행일 때만 뜬다.** 배포 주소 탭은 연결이 끊기면 Streamlit이 오류 창을 띄운다.
11. **Community Cloud 약관은 금융 정보와 민감한 개인정보 처리를 금지하고, 서버는 미국에 있다.** 시험과 시연은 가상 샘플만 쓰고, 실제 계약서는 '가리고 올리기'가 꼭 필요한 조건이다.
12. **API 키는 작업 공간(workspace) 하나에 묶어 만들고, 만료는 7일로 한다.** 1일로 만들면 오늘 오후에 만든 키가 내일 발표 무렵에 끊긴다.

### 민서가 콘솔에서 볼 것

- **Rate limits 페이지**(platform.claude.com/usage/limits): 등급이 Evaluation인지 본다. 새 조직은 공개 숫자보다 낮은 Evaluation 등급으로 시작할 수 있다. Opus 5.5의 분당 요청·입력·출력 한도 세 숫자를 적는다. 크레딧을 사도 등급은 바로 오르지 않는다. 더 필요하면 같은 페이지의 Request tier increase로 요청한다.
- **Billing 페이지**(platform.claude.com/settings/billing): 크레딧 잔액, 자동 충전, 내가 건 사용 한도, 등급 월 상한을 본다. 호출은 크레딧 잔액, 내가 건 한도, 등급 월 상한 가운데 먼저 닿는 곳에서 멈춘다. Evaluation 등급의 월 상한은 문서에 없고 콘솔에서만 보이니 숫자를 적는다. 크레딧은 사는 즉시 쓸 수 있다.
- **작업 공간:** 기본 작업 공간(Default Workspace)에는 사용 한도를 걸 수 없다. 시연 앱 예산을 지키려면 새 작업 공간을 만들어 한도를 걸고, 그 작업 공간에 묶은 키를 쓴다. 실험용 두 번째 앱까지 나누려면 작업 공간과 키를 2개씩 만든다. 프롬프트 캐시는 작업 공간마다 따로다.
- **키:** 작업 공간 하나에 묶지 않은 키는 모든 요청에 작업 공간 머리글이 있어야 해서 400이 난다. 만료는 만들 때만 고를 수 있다(3시간, 1일, 7일, 30일, 직접 입력, 없음). 만료된 키는 401이다.

## 2장 Claude API 호출 설정

### 모델과 가격

- 모델 ID `claude-opus-5-5`(날짜 없는 고정 판). 100만 토큰당 입력 4달러, 출력 20달러. 5분 캐시 쓰기 5달러, 1시간 캐시 쓰기 8달러, 캐시 읽기 0.20달러(입력의 0.05배).
- 문맥 100만 토큰, 최대 출력 128K, 생각은 적응형(늘 켜짐), 기본 effort는 medium, 믿을 만한 지식 기준일 2026년 6월.

### 요청에 넣는 것

- **effort:** 값은 low, medium, high, xhigh, max. `output_config` 객체 안의 `effort` 키로 넣는다. 베타 헤더는 필요 없다. 기본값 medium을 직접 적어도 동작과 캐시는 생략할 때와 같다. effort를 바꾸면 프롬프트 캐시가 새로 쌓인다고 보고, low와 medium 비교는 수준별로 묶어서 차례로 돌린다.
- **thinking:** 보내지 않는다. 안 보내면 adaptive를 보낸 것과 같다. `disabled`, `enabled`와 `budget_tokens`, `between_tools`는 모두 400이다. 생각 토큰은 화면에 안 보여도(display 기본값 omitted) 전부 출력 토큰으로 과금되고 `max_tokens`에 들어간다. 응답의 첫 블록이 생각 블록일 수 있으니, 결과는 type이 text인 블록에서 읽는다.
- **max_tokens 16,000:** 기준 자료가 권하는 값이다(스트리밍 없이 약 16K를 넘기면 스트리밍으로 바꾸라고 한다). SDK는 timeout을 직접 주지 않았을 때만 max_tokens가 21,333보다 크면 요청 전에 ValueError를 낸다. 우리는 timeout을 직접 주니 이 검사는 꺼지고, 길어지면 APITimeoutError로 끝난다.
- **사진 먼저, 글 나중.** 사진이 여러 장이면 각 사진 앞에 '사진 1:' 같은 짧은 라벨 글을 둔다. PDF도 요청 글보다 앞에 둔다.

SDK 2.x는 기본으로 API 버전 2026-10-21을 보낸다. 이 버전에서는 temperature 등이 어떤 값이든 400이다.

### 시간 제한과 재시도

- SDK 기본값: 시간 제한 10분(연결 5초), 재시도 2회. 재시도 대상은 연결 오류, 시간 초과(APITimeoutError는 APIConnectionError의 하위라 재시도된다), 408, 409, 429, 500 이상(529 포함)이다. 대기는 0.5초에서 두 배씩 최대 8초다. 서버가 retry-after를 보내면 상한 없이 그만큼 기다린다.
- 그래서 timeout 120초에 max_retries 1이면 멈춘 요청 하나에 화면이 최악 약 240초(+retry-after) 기다리고, 같은 분석을 두 번 시작한다. SDK 설정만으로는 '연결 오류는 재시도, 시간 초과는 안 함'으로 나눌 수 없다.
- **권장:** 클라이언트를 timeout 90~120초, `max_retries=0`으로 만든다. 앱 코드가 연결 오류(시간 초과 제외), 5xx(529 포함), retry-after가 짧은 429만 1회 다시 보낸다. 시간 초과는 바로 '다시 시도' 안내로 넘긴다. 잡는 순서는 APITimeoutError를 APIConnectionError보다 먼저 둔다.

### 구조화 출력

- **권장 경로:** `client.messages.create`에 `output_config`로 effort와 format을 함께 넣는다. format은 type `json_schema`와 schema이고, schema는 `anthropic.transform_schema(결과 Pydantic 모델)`로 만든다(parse가 보내는 것과 같다). 받은 뒤 3장 순서로 처리하고, text 블록을 `모델.model_validate_json`으로 검사한다.
- **SDK가 스키마에서 빼는 제약:** `transform_schema`는 최소한의 것(type, anyOf, enum, description, properties, required, items, 지원 문자열 format 등)만 남긴다. `max_length`, `min_length`, `ge`/`le`, `pattern`, `maxItems`, 2 이상의 `minItems`, `const`, `default`는 서버 스키마에서 빠지고 설명 글로만 간다. 그런데 받은 뒤 원래 Pydantic 모델로 검사하면 이 제약을 어긴 값에서 ValidationError가 난다. 그래서 Pydantic 모델에 이런 제약을 걸지 않고, 길이와 개수는 코드가 자른다.
- **명시 한도:** 한 요청의 strict 스키마를 다 합쳐 선택 칸(required에 없는 칸) 24개, anyOf나 'X 또는 null' 칸 16개. 그래서 모든 칸을 required로 두고 기본값을 주지 않는다. Optional 대신 '알 수 없음' 보기나 빈 글을 쓴다. 별도로 문법 크기 한도가 있어 넘으면 400 'Schema is too complex for compilation'이다.
- **보기가 정해진 칸:** 보기 2개 이상인 Literal로 두고 보기 글자는 한글로 쓴다(주의, 확인 필요, 괜찮음). 구조화 출력은 영어 보기의 대소문자를 보장하지 않아서, 대소문자가 바뀌면 ValidationError가 난다. 보기가 하나뿐인 Literal은 const가 되어 서버가 강제하지 않는다.
- **칸 이름:** reasoning, thinking, trace 같은 이름을 쓰지 않는다. 생각 과정을 그대로 쓰라고 하면 reasoning_extraction 거절이 날 수 있다. 이 거절은 출력 전에 나도 과금되고, 대체 모델로도 넘어가지 않는다. 쉬운 설명 칸은 explanation처럼 짓는다.
- **검사 오류 메시지:** Pydantic 모델 설정에 `hide_input_in_errors=True`를 둔다. 기본값이면 ValidationError 문자열에 실패한 값(계약서 인용, 개인정보)이 그대로 찍힌다.
- **형식(문법) 캐시:** 새 스키마는 첫 요청 때 문법을 만드느라 더 걸리고, 마지막 사용부터 24시간 캐시된다. 칸 구조를 바꾸면 무효가 되고, name이나 description만 바꾸면 그대로다. max_tokens 0짜리 데우기 요청은 구조화 출력과 함께 쓰면 거부되므로, 데우기는 실제 분석 1회로 한다.

### 서버측 대체 모델 (베타, 켤지는 팀이 정한다)

- 베타 헤더 `server-side-fallback-2026-07-01`, 매개변수 `fallbacks`에 `default`. 이 인자는 `client.beta.messages`의 create와 parse에만 있고, 일반 `client.messages`에는 없다.
- 대체는 안전 분류기 거절(stop_reason refusal)일 때만 일어난다. 429, 과부하, 서버 오류는 대체하지 않는다. reasoning_extraction 거절은 추천 대체 모델이 없어 그대로 온다.
- 답한 모델은 응답의 `model`, `usage.iterations`, content 맨 앞의 fallback 블록으로 안다. 한 번 대체된 대화는 약 1시간 동안 대체 모델로 바로 갈 수 있다(조직 단위, best-effort). 그래서 정답표와 리허설 기록에 실행마다 model을 적는다.
- 대체 모델과 그 단가는 공개되지 않았다(예: Opus 5나 4.8이면 입력 5달러·출력 25달러로 더 비싸다). Batches API에서는 못 쓴다.
- 이 앱에서 얻는 것은 작다. 계약서 읽기에서 cyber·bio 거절은 드물고, 생길 만한 reasoning_extraction은 대체로 막지 못한다. 공식 안내서는 Opus 5.5에 대체 설정을 권하므로 켜는 것이 틀리지는 않다. beta 클라이언트를 써야 하는 점, 대화 고정, 정답표의 답한 모델이 바뀌는 점과 견줘 킥오프에서 정한다. (확신: 보통. 대체와 구조화 출력을 함께 실제로 돌려 보지는 않았다.)

### 프롬프트 캐시

- system의 마지막 블록(기준 목록 끝)에 `cache_control` `{type: ephemeral}`을 직접 붙인다. 요청 맨 위의 `cache_control` 인자(자동 캐싱)는 쓰지 않는다. 자동 캐싱은 매번 바뀌는 마지막 블록(새 사진과 요청 글)에 표시를 붙여서, 적중 없이 1.25배 쓰기 값만 낸다. 일반 `client.messages.parse`에는 이 최상위 인자가 아예 없다(TypeError).
- Opus 5.5 최소 캐시 길이 512토큰. 짧으면 오류 없이 캐시만 안 된다. 수명은 요청이 시작된 때부터 5분이고, 읽힐 때마다 다시 5분이 된다. ttl `1h`로 1시간도 된다(쓰기 2배 값).
- system 글은 매 실행 글자 하나 다르지 않게 만든다. 시간이나 세션 번호처럼 요청마다 바뀌는 값은 system에 넣지 않는다. 잘려서 다시 보낼 때는 system과 스키마를 고치지 말고 user 메시지 끝에 지시를 덧붙인다. 스키마(format)나 effort를 바꾸면 캐시가 깨진다.
- 캐시 읽기 토큰은 분당 입력 한도(ITPM)에 세지 않는다. 같은 앞부분으로 동시에 보낸 요청은 첫 응답이 시작되기 전에는 서로의 캐시를 읽지 못한다. 정답표를 차례로 돌리는 이유다.

### 사진과 PDF의 API 한도

- 사진 형식은 JPEG, PNG, GIF, WebP뿐이다(HEIC 없음). 1장은 base64 기준 10MB, 가로·세로 각 8,000px까지. 요청 전체는 128MB까지(넘으면 413). 한 요청에 사진이 20장을 넘으면 더 엄격한 크기 한도가 붙는다.
- Opus 5.5는 고해상도 등급이라 '긴 변 2,576px'와 '그림 토큰 4,784개'를 둘 다 지키도록 서버가 줄인다. 그림 토큰은 (가로÷28 올림) × (세로÷28 올림)이다.
- 긴 변 2,200px인 4:3 사진(2,200×1,650)은 4,661토큰이라 서버가 다시 줄이지 않는다. 16:9(3,555), 3:2(4,187), A4 비율(4,424)도 괜찮다. 그런데 짧은 변이 1,680px를 넘으면(5:4나 1:1처럼 정사각형에 가까우면) 4,784를 넘어서 서버가 한 번 더 줄이고, 두 번 줄이면 글자가 흐려질 수 있다. 그래서 공식 Coordinates 문서의 크기 계산 규칙에 고해상도 값(긴 변 2,576px, 그림 토큰 4,784개)을 넣어 나온 크기로 한 번만 줄인다. 4:3 사진은 2,212×1,659(4,740토큰)가 되어 2,200px와 거의 같다. 2,200px를 그대로 쓰려면 줄인 뒤 토큰 계산이 4,784를 넘을 때 그 안으로 더 줄이는 조건을 붙인다.
- Claude는 사진의 EXIF를 읽지 않는다. 방향은 앱이 미리 바로잡아 보낸다. 세게 또는 여러 번 압축한 JPEG는 글자를 읽기 어렵고, 200px 미만 사진은 틀리기 쉽다.
- PDF는 document 블록(base64, application/pdf)으로 보낸다. Claude API 직접 호출 기준 요청 128MB, 600쪽까지다(32MB는 다른 플랫폼 값). 쪽마다 글자 1,500~3,000토큰에 쪽 그림 토큰이 더해진다. 암호나 암호화가 걸린 PDF는 받지 않는데, 이때의 상태 코드와 문구는 문서에 없다. 앱의 PDF 크기·쪽수 상한은 API 한도가 아니라 비용과 시간으로 작게 정한다(예: 10~20MB).
- Citations는 쓰지 않는다. 구조화 출력과 함께 쓰면 400이고, 사진과 스캔 PDF는 인용할 수 없다.

### 비용 어림

- 1회 비용 = (입력 토큰 × 4 + 출력 토큰 × 20) ÷ 100만 달러.
- 사진 1장 약 4,661토큰이면 약 0.019달러. 지시문과 기준 1만 토큰은 캐시 없으면 0.04달러, 캐시 쓰기면 0.05달러, 캐시 적중이면 0.002달러.
- 생각을 포함한 출력이 3천~8천 토큰이면 0.06~0.16달러. 합계 1회 약 0.08~0.23달러로 설계의 어림과 맞다. 출력이 16,000까지 차면 1회 약 0.39달러다.
- 다시 보내면 그 회는 두 배다. 분석 도중 다시 실행으로 끊긴 호출도 끝까지 돌아 비용이 나간다. 일부 거절도 과금된다. 10쪽 PDF는 입력만 최대 약 0.31달러까지 갈 수 있다.
- 예산 한도는 200회 × 0.4달러 = 약 80달러를 기준으로 잡는다. 18:00 측정 때 usage의 input_tokens, cache_creation_input_tokens, cache_read_input_tokens, output_tokens를 적어 실제 값으로 바꾼다.

### 21:00 모델 교체 비상안

모델 이름만 바꾸면 기본 effort, 생각 끄기 가능 여부, 대체 모델 동작, 토큰 수, 가격이 조용히 바뀐다. 그래서 모델, 생각 설정, effort, fallbacks 켬/끔을 한 묶음 설정으로 두고, 21:00 전에 후보 하나와 그 묶음을 미리 정한다. 바꾸면 정답표를 다시 돌린다. 아래는 점검 단계에서 공식 모델 표와 기준 자료로 확인한 내용이다.

## 3장 응답 처리와 오류

### 응답을 받은 뒤 순서

1. `stop_reason`이 `refusal`이면 거절이다. 다시 보내지 않고 '분석하지 못했다'를 띄운다. 거절은 HTTP 200으로 온다. 출력 전에 거절되면 content가 비어 있고 `stop_details.category`로 분류를 볼 수 있다.
2. `max_tokens`면 잘림이다. 출력을 줄이라는 지시를 user 메시지 끝에 덧붙여 1회 다시 보낸다.
3. 그 밖이면 type이 text인 블록을 Pydantic 모델로 검사한다. ValidationError면 형식 오류로 처리한다.

이렇게 해야 거절, 잘림, 형식 오류를 확실히 가르고, 답한 모델과 usage와 request id를 로그에 남길 수 있다.

### parse 도우미를 쓰면 생기는 일 (SDK 2.5.0 소스)

- JSON을 쓰던 중 잘리거나 형식이 어긋나면 `pydantic.ValidationError`가 parse 밖으로 나오고, stop_reason·usage·request id가 든 응답 객체를 받지 못한다. 이 오류는 anthropic 오류가 아니고 재시도도 안 된다.
- 생각하던 중에 잘려 text 블록이 없으면 예외 없이 `parsed_output`이 None이다. 아주 작은 max_tokens로 시험하면 이 경로로 간다.
- 출력 도중 거절되면 거절 문장이 JSON이 아니어서 ValidationError가 날 수 있다.
- 그래서 parse를 쓰면 ValidationError가 났을 때 응답 객체를 받지 못해 거절과 잘림을 구분하지 못하고, 거절도 다시 보내게 된다. parsed_output이 None으로 오면 응답의 stop_reason을 따로 봐야 한다. create를 권하는 이유다.

### 예외를 잡는 순서 (anthropic 2.5.0 이상 전제)

EnforcedSpendLimitReachedError → RateLimitError → APITimeoutError → APIConnectionError → InternalServerError(529 OverloadedError 포함) → BadRequestError(문구로 구분) → 나머지 APIStatusError(402 등).

2.5.0에서 오류 종류가 정리되었다. 그보다 옛 판에서는 InternalServerError로 529를 잡지 못한다. 판 고정이 필요한 이유다.

### 사용 한도 오류 넷

| 경우 | 상태 | 알아보는 법 | SDK 재시도 |
|---|---|---|---|
| 우리가 콘솔에서 건 조직·작업 공간 한도 | 400 | 문구가 'You have reached your specified'로 시작 | 안 함 |
| 등급 월 상한(Start 500달러) | 429 | error.details.error_code가 enforced_spend_limit_reached, EnforcedSpendLimitReachedError | 함(429라서). 하지만 다음 달 1일까지 계속 실패 |
| 크레딧 소진 | 400(GitHub 이슈 보고, 공식 문서엔 상태 없음) | 문구에 'credit balance' | 안 함 |
| 결제 정보 문제 | 402 billing_error | 전용 종류 없음(APIStatusError) | 안 함 |

넷 다 다시 보내지 않고 '사용 한도에 닿았다, 저장본으로 보여 준다'를 띄운다. 등급 월 상한은 retry-after 없이 다음 달 1일 00:00 UTC까지 막힌다.

429와 529는 다르다. 429는 우리 조직의 분당 한도, 갑자기 늘 때의 가속 한도, 월 상한 때문이고 retry-after가 붙을 수 있다. 529는 API 전체가 잠시 과부하라는 뜻이다.

### 로그와 오류 화면

- 로그에는 오류 클래스 이름, request_id, 걸린 시간만 남긴다. request_id는 응답 객체의 `_request_id`(밑줄로 시작하지만 공개 속성)나 오류 본문에 있고, 개인정보가 아니다.
- ValidationError나 예외 메시지를 문자열로 찍지 않는다. 계약서 인용이 섞여 있을 수 있다.
- print에는 `flush=True`를 준다. 그래야 Cloud logs에 바로 나온다.
- 배포 앱에서 `ANTHROPIC_LOG=debug`를 켜거나 로그 수준을 DEBUG로 올리지 않는다. SDK가 요청 본문(base64 사진, 지시문)을 통째로 로그에 남긴다.
- **개발 스위치:** 로컬 실행 명령에서만 주는 환경변수가 있으면 traceback을 화면과 터미널에 그대로 보인다. 그래야 Claude Code에게 오류를 복사해 고쳐 달라고 할 수 있다. 환경변수가 없으면(배포) 화면에는 일반 문장만 띄운다.
- `except`는 Exception까지만 쓴다. `st.rerun`과 `st.stop`이 내는 예외는 BaseException 계열이라, 맨 except나 BaseException으로 잡으면 다시 실행과 멈춤이 고장 난다.
- 걸린 시간은 화면의 스피너 초를 옮기지 말고 Python에서 호출 전후로 따로 잰다.

## 4장 Streamlit 동작 (1.66.1 기준)

이 Mac의 1.50.0과 다른 점이 많다. 1.57.0부터 웹 서버가 Tornado에서 Starlette·Uvicorn으로 바뀌었고, 위젯의 `max_upload_size`는 1.53.0, `on_change='ignore'`는 1.65.0부터 있다. 옛 `experimental_get_query_params`·`experimental_set_query_params`는 1.54.0에서, `use_column_width`는 1.61.0에서 없어졌다.

### 파일 올리기 (st.file_uploader)

- `type`에 확장자 목록을 준다. 점과 대소문자는 상관없고, jpg를 넣으면 jpeg도 저절로 더해진다. 문서는 이 검사를 '보안 보장이 아닌 최선 노력'이라고 한다. 그래서 Pillow로 실제로 열어 보는 검사는 그대로 둔다.
- `accept_multiple_files`는 기본값 False(1개)로 둔다.
- 기본 한도는 파일당 200MB다. 위젯의 `max_upload_size`와 config.toml `[server]`의 `maxUploadSize`(MB)를 둘 다 같은 낮은 값으로 정한다. 최신 업로드 경로가 server.maxUploadSize 기준으로도 검사하기 때문이다. 사진과 PDF를 한 칸에서 받으면 한도도 하나라서, PDF만 더 작게 막으려면 `UploadedFile.size`로 따로 검사한다.
- 형식이 틀리거나 한도를 넘은 파일은 브라우저에서 거절되어 Python에 오지 않는다. 업로더 안에는 영어 거절 문구만 뜬다. 그래서 한국어 안내(허용 형식, 최대 크기, 'HEIC는 스크린샷이나 JPG로 바꿔 주세요')를 label·help와 칸 바로 아래 고정 글로 늘 보여 준다. 시연 대본에는 영어 문구가 보일 수 있다고 적어 둔다.
- `type`에 heic를 넣지 않는다. 아이폰 사파리는 업로더가 받는 형식을 보고 사진 보관함 사진을 JPEG로 바꿔 주는데, heic를 받는다고 알리면 HEIC 그대로 올 수 있다. 지금 아이폰이 어떻게 동작하는지는 시험으로 확인한다(9장).
- 받은 값은 BytesIO 하위 클래스라 `getvalue()`로 메모리에서 읽는다. 다만 1MB가 넘는 업로드는 Starlette가 받는 동안 임시 파일을 잠깐 거친 뒤 메모리로 옮겨진다. 그래서 '앱 코드는 디스크에 쓰지 않는다'가 정확한 표현이다.

### 다시 실행과 분석 중 화면

- 폼 밖 위젯을 건드리면 스크립트가 처음부터 다시 돈다. 실행 중에 조작이 들어오면 지금 실행에는 멈춤 요청만 가고 새 실행이 곧바로 시작된다(Community Cloud는 fastReruns를 켜 둔 채로 강제한다). 진행 중인 Claude 호출은 끝까지 돌아 비용이 나가지만, 결과는 session_state에 쓰는 줄에서 버려진다. 새 실행이 다시 호출에 닿으면 호출이 두 번 나간다.
- 흐려진 옛 위젯도 눌린다. 메뉴의 Rerun과 키보드 R은 모든 방문자가 쓸 수 있고 끌 수 없다. 연결이 끊겼다 다시 붙을 때와 저장소에 push할 때(Cloud가 runOnSave를 강제)도 다시 실행된다.
- **권장 순서:**
  1. '확인하기'의 `on_click` 콜백에서 '분석 요청' 깃발을 켠다.
  2. 그 실행에서 값을 가진 위젯(올리기 칸 등)은 그대로 그리되 `disabled=True`로 막는다. 숨기면 안 된다. 한 실행에서 그리지 않은 위젯은 값이 지워지고, file_uploader는 값을 지키는 persist_state를 지원하지 않는다. 숨겨도 되는 것은 단추뿐이다. 올리기 칸의 type 같은 매개변수도 실행마다 바꾸지 않는다(바꾸면 초기화된다).
  3. 호출 직전에 깃발을 끄고 '분석 시작' 표시를 남긴다. 세션 횟수도 호출 전에 센다.
  4. 결과를 session_state에 넣고 표시를 지운 뒤 `st.rerun`으로 위젯을 다시 켠다.
  5. 새 실행에서 '분석 시작' 표시는 있는데 결과가 없으면 '분석이 중간에 끊겼어요. 다시 눌러 주세요'를 띄우고 표시를 지운다.
- 결과 구역 전체는 `st.empty`로 만든 자리 하나에 그리고, 분석을 시작하면 그 자리를 대기 화면으로 바꾼다. 그래야 지난 카드가 흐리게 남지 않는다.
- '파일이 바뀌면 이전 결과 지우기'는 업로더의 `on_change` 콜백에서 session_state의 결과를 지운다.
- 사진 준비는 새 파일(file_id가 바뀔 때)일 때 한 번만 하고, 준비한 JPEG 바이트를 session_state에 둔다. 미리보기, 왼쪽 대조 사진, API 입력은 모두 이 바이트를 쓴다.
- 사용자 파일이나 결과가 들어가는 함수에는 `st.cache_data`와 `st.cache_resource`를 쓰지 않는다. 이 캐시는 기본으로 모든 사용자가 함께 쓴다. 꼭 필요하면 `scope="session"`(1.53.0부터)으로 둔다. 모든 사용자가 함께 써도 되는 것은 Anthropic 클라이언트와 하루 카운터뿐이다. 사용자 값은 모듈 전역 변수에도 두지 않는다.
- 대기 화면에 '분석이 끝날 때까지 이 화면을 켜 두세요'를 적는다. 휴대폰에서 문자 앱으로 갔다 오거나 화면이 꺼지면 연결이 끊겨 결과가 버려질 수 있다.

### 화면 부품

- **지난 초:** `st.spinner(show_time=True)`(1.42.0부터). 브라우저가 0.1초 단위로 직접 세서, Python이 호출을 기다리는 동안에도 숫자가 올라간다. 스피너는 0.5초가 지나야 나타나서 실제보다 약 0.5초 늦게 센다. `st.status`에는 경과 시간 옵션이 없다. 스레드나 타이머를 따로 만들지 않는다(앱 코드의 멀티스레딩은 공식 지원이 아니다).
- **질문 복사 상자:** `st.code`에 `wrap_lines=True`(1.38.0부터), `language=None`(기본값이 python이라 한국어에도 색칠이 된다). 복사 단추는 마우스를 올리거나 키보드 초점이 갈 때만 보이고 터치용 규칙이 없다. 휴대폰에서는 안 보이거나 안 눌릴 수 있으니 '길게 눌러 복사하세요' 안내를 늘 둔다. 복사 기능은 HTTPS에서만 되므로 휴대폰 시험은 배포 주소에서 한다.
- **카드:** `st.container(border=True)`(1.29.0부터, 기본값이면 높이를 고정할 때만 테두리가 생긴다), 이름표는 `st.badge`(1.44.0부터, color는 red·orange·yellow·blue·green·violet·gray·primary), 근거는 `st.expander`. 빨강·노랑·초록 실제 색은 config.toml `[theme]`의 redColor·yellowColor·greenColor로 정한다(기본 #ff4b4b, #faca2b, #21c354). CSS는 쓰지 않는다.
- **열:** `st.columns`는 화면이 640px 이하이면 위아래로 쌓인다(wrap=True가 기본). 왼쪽 열이 위로 가므로 휴대폰에서는 사진이 먼저 나오고 카드가 밀린다. 사진을 작은 미리보기나 접기 상자로 두는 것을 고려한다. 열 안 버튼 이름은 1.63.0부터 말줄임으로 잘리니 짧게 짓는다. 넓은 배치는 `st.set_page_config(layout="wide")`.
- **사진 보여 주기:** `st.image`에는 준비한 이미지(방향을 바로잡고 줄인 것)를 넣는다. Streamlit은 EXIF 방향을 고치지 않고, 원본 바이트를 넣으면 위치 정보 같은 EXIF까지 그대로 브라우저로 간다. 너비는 `width`('content', 'stretch', 픽셀 정수)로 주고 `use_column_width`·`use_container_width`는 쓰지 않는다.
- **PDF를 올렸을 때 왼쪽 칸:** `st.image`에 PDF를 넣으면 오류다. MVP에서는 '원본 PDF를 내 기기에서 열어 대조해 주세요'와 파일 이름만 보인다. `st.pdf`는 streamlit[pdf]를 따로 깔아야 한다.
- **글자 그대로 보이기:** `st.markdown`은 물결표(~, 취소선), `$…$`(수식), `:이름:`(이모지·아이콘), `:red[…]`(색)를 해석한다. 원문 인용은 마크다운을 해석하지 않는 `st.text`나 `st.code`(language=None, wrap_lines=True)로 보인다. AI 설명을 마크다운으로 그릴 때는 이 기호들을 글자 그대로 바꾸는 함수 하나를 거친다. 가상 샘플에 '1~2개월', '$', '특약:수리:' 같은 글을 넣어 확인한다.
- **저장본 결과 파일 만들기:** 결과 화면에 `st.download_button`(on_click='ignore'를 주면 다시 실행이 일어나지 않는다)으로 '결과 파일 내려받기'를 둔다. 받은 JSON을 samples 폴더에 커밋한다. 파일에는 AI의 원래 결과와 함께 답한 모델, effort, 분석 시각(한국 시간), 지시문·기준 목록 버전을 넣는다. 이 단추는 개발용 주소 옵션이 있을 때만 보여도 된다. 결과 형식이나 기준 번호를 바꾸면 저장본을 다시 만든다.

### 상태와 설정

- **session_state:** 브라우저 탭(세션)마다 따로이고 새로고침하면 사라진다. 깨끗하지 않게 끊긴 연결은 같은 세션에 다시 붙어 값이 남는다(1.61.0부터). 탭을 닫으면 연결이 끊기고 기본 120초 뒤 서버 메모리에서 정리된다.
- **하루 상한:** `st.cache_resource(show_spinner=False)`로 만든 공유 객체 하나에 날짜, 횟수, `threading.Lock`을 두고 잠금 안에서 확인과 증가를 한 번에 한다. 날짜는 한국 시간(UTC+9)으로 계산한다(서버 시간대는 확인 못 했다). 세는 단위는 실제 API 호출이다(다시 보내기 포함, 저장본 보기 제외). 앱이 다시 시작되거나 잠들거나 재배포·Reboot되면 0으로 돌아가는 '느슨한 상한'이다. 'Clear cache' 메뉴와 단축키 C는 개발자에게만 보인다. 세션당 횟수는 session_state로 센다.
- **주소 옵션:** `st.query_params`(1.30.0부터)로 읽는다. 값은 늘 문자열이라 `'1'`과 비교한다. embed와 embed_options는 예약어다.
- **키(st.secrets):** 맨 윗단(섹션 없이) `ANTHROPIC_API_KEY`로 넣으면 환경변수로도 들어가서 `Anthropic()`이 알아서 읽는다. 파일이 없을 때 읽으면 FileNotFoundError, 키가 없으면 KeyError가 난다(`.get`도 파일이 없으면 오류). 키는 '확인하기'를 누른 뒤에만 읽고, 저장본 화면 경로는 st.secrets를 건드리지 않는다. `st.write(st.secrets)`나 print로 내보내지 않는다. 1.66.0부터는 secrets.toml을 해석하지 못하면 시작할 때 로그에 오류가 남는다.
- **매직 끄기:** config.toml `[runner]`에 `magicEnabled = false`. 변수 이름만 한 줄 적어도 화면에 그려 버리는 기능이라, 실수로 키나 결과를 띄울 수 있다.
- **한글 글꼴:** `[[theme.fontFaces]]`(1.44.0부터)로 정한다. woff2 파일은 앱 옆 static 폴더에 두고 `server.enableStaticServing = true`로 싣는다('app/static/파일이름'). 외부 글꼴 주소(1.50.0부터)는 방문자 IP가 글꼴 업체로 가고 인터넷 없는 저장본에서 안 뜨니 피한다. 글꼴 목록 끝에 sans-serif를 둔다.
- **Streamlit이 스스로 띄우는 것:** st.toast는 부를 때만 뜬다. 연결이 끊길 때의 'Connection error' 창(영어)은 끄는 설정을 찾지 못했다. 스크립트가 도는 동안 오른쪽 위에 실행 중 표시도 뜨는데, 끌 수 있는지는 확인하지 않았다. 끌 수 있는 것은 끈다: 캐시 함수의 스피너(show_spinner=False), 오류 상자(3장 개발 스위치), 폐기 경고(폐기된 매개변수를 쓰지 않는다).

### .streamlit/config.toml에 넣는 것

`[server]` maxUploadSize(낮게), 글꼴을 쓰면 enableStaticServing, `[runner]` magicEnabled = false, `[theme]` 색과 글꼴. showErrorDetails는 넣지 않는다(5장). headless와 포트는 config.toml이 아니라 로컬 실행 명령에 둔다. 이 파일과 .gitignore, static 폴더의 주인은 앱 담당이다.

## 5장 Community Cloud 배포

- **배포:** share.streamlit.io의 Create app에서 저장소, 브랜치, 진입 파일, 하위 주소(App URL)를 고른다. 배포하는 사람은 그 저장소에 admin 권한이 있어야 한다. push는 거의 바로 반영된다. GitHub에서 오는 갱신은 1분에 5번까지다. 하위 주소는 QR을 만든 뒤 바꾸지 않는다(바꾸면 옛 주소는 404).
- **작업 폴더:** Community Cloud는 모든 앱을 저장소 루트에서 실행한다. criteria.csv, instructions.txt, samples 경로는 저장소 루트 기준으로 쓰고, 로컬에서도 저장소 루트에서 `streamlit run`을 한다.
- **파이썬 판:** Advanced settings의 Python version에서 3.12를 직접 고른다. 문서끼리 기본값 설명이 어긋나서('기본 3.12'와 '새 판을 곧 기본값으로 따라간다') 기본값을 믿지 않는다. 배포 뒤에는 못 바꾸고, 바꾸려면 앱을 지우고 다시 배포하며 Secrets와 하위 주소를 다시 넣는다. runtime.txt나 .python-version은 쓰지 않는다. 빌드 로그에서 실제 판을 확인한다.
- **Secrets:** 배포 때 Advanced settings의 Secrets 칸에(배포 뒤에는 앱 설정에서) secrets.toml 내용을 붙여 넣는다. 앱마다 따로다.
- **공개와 비공개:** 앱은 저장소의 공개 여부를 물려받는다. 공개 앱은 주소를 아는 누구나 보고 검색 엔진에 매주 자동 색인된다. 비공개 저장소는 Linked accounts에서 권한을 한 번 더 줘야 한다. 비공개 저장소의 앱은 비공개로 시작하고, 비공개 앱은 워크스페이스 개발자와 이메일로 초대한 사람만 본다. 그래서 심사위원 QR을 쓰려면 첫 배포 뒤 앱 설정의 Sharing에서 앱을 공개로 바꾸고(저장소는 비공개로 둬도 된다), Streamlit에 로그인하지 않은 휴대폰으로 QR 주소가 열리는지 확인한다. 비공개 앱은 계정당 한 번에 1개뿐이라 실험용 두 번째 앱과도 부딪친다(시연 앱을 먼저 공개로 바꾸면 풀린다). 공개 저장소면 코드와 지시문, 기준 목록이 공개된다(키는 Secrets에만 있어 안전하다). 저장소 공개 여부는 팀이 정한다.
- **두 번째 앱:** 같은 저장소의 다른 브랜치로 하나 더 띄울 수 있다. 파이썬 판과 Secrets는 앱마다 따로 정하고, 각 브랜치 루트의 config.toml을 읽는다. 정답표와 effort 비교는 이 앱이나 로컬에서 한다. 걸린 시간 측정은 Cloud에서 해야 하니(로컬은 사진 준비에 쓰는 CPU가 Cloud와 다르다) 이 앱에서 차례로 하고, 이 앱이 아직 없으면 시연 앱에서 잰다. 이 앱은 카운터가 따로라 시연 앱의 세션·하루 카운터를 쓰지 않는다. 시연 앱의 예산까지 지키려면 이 앱과 로컬 실행은 따로 만든 작업 공간에 묶은 키로 돌린다(0장 '작업 공간').
- **Cloud가 강제하는 설정 다섯:** client.showErrorDetails = false, runner.fastReruns = true, server.runOnSave = true, server.enableXsrfProtection, browser.gatherUsageStats. 나머지 config.toml 값은 그대로 쓰인다.
  - showErrorDetails false는 예전 값으로 'stacktrace'와 같다. 잡지 않은 예외가 나면 화면에 예외 종류와 traceback(코드 줄, 파일 경로)이 뜨고 메시지만 일반 문장으로 바뀐다. config.toml에 적어도 소용없다.
  - 대책: 앱 본문 전체를 try/except(Exception)로 감싸 어떤 예외도 Streamlit까지 올라가지 않게 한다(주 대책). app.py 맨 위에서 다른 st 명령보다 먼저, 개발 스위치가 꺼졌을 때만 `st.set_option("client.showErrorDetails", "none")`을 부른다(보조). 소스로 보면 실행 중에 값을 덮어써서 Cloud 강제값을 이길 것으로 보이지만 실행해 보지는 않았다. 첫 배포 때 일부러 예외를 한 번 내서 화면과 Cloud logs를 확인한다.
  - runOnSave 때문에, 누가 배포 주소로 시험하거나 시연하는 동안 그 브랜치에 push하면 접속 중인 모든 세션이 다시 실행되고 진행 중인 분석이 버려진다.
- **잠들기:** 12시간 동안 접속이 없으면 잠든다. 보기 권한이 있는 누구나 'Yes, get this app back up!' 단추로 깨울 수 있다. 깨우는 데 걸리는 시간은 문서에 없다. push로 깨우려 하지 않는다. 발표 전에 배포 주소를 직접 열어 깨우고 샘플을 한 번 돌린다.
- **자원(2024년 2월 기준 대략):** CPU 0.078~2코어, 메모리 690MB~2.7GB, 저장 공간 50GB. 넘으면 'over its resource limits' 화면이 뜨고, Manage app에서 Reboot한다. Reboot하면 메모리가 비워져 접속 중인 모든 세션의 결과와 하루 카운터가 사라진다. 메모리는 모든 사용자가 함께 쓴다. 동시 사용자 수 제한은 문서에 없다.
- **로그:** 오른쪽 아래 Manage app의 Cloud logs(Download log로 받기). 저장소에 쓰기 권한이 있는 사람만 본다. 잡지 않은 예외는 전체 traceback이 로그에 남는다.
- **서버와 약관:** 서버는 미국에만 있고 바꿀 수 없다. 개인정보 정책(streamlit.io/privacy)은 Snowflake Privacy Notice를 따른다. 이용 약관(2025-11 갱신)의 Community Cloud 조항은 개인적·비상업 용도(교육 등)만 허용하고, 금융 정보·건강 정보·생체 정보와 그 밖의 민감한 개인정보를 처리하거나 올리게 하는 것을 금지하며, 보는 사람에 대한 법적 의무는 앱 주인에게 있다고 적는다. 계약서에는 주민번호·계좌번호가 흔히 들어 있으니, 시험·시연은 가상 샘플만 쓰고 실제 사용자는 가리고 올리게 한다. 대회 뒤 실제 서비스로 이어 가려면 다른 배포처를 검토한다.
- 참고로 Vercel 함수는 요청 본문이 4.5MB까지라(넘으면 413) 휴대폰 원본 사진이 넘기 쉽다. 실행 시간은 Hobby 300초다.

## 6장 사진·PDF 준비 (Pillow·pypdf)

### 사진 준비 순서

1. `Image.open`을 try로 감싼다. 열 때 머리 정보로 크기만 먼저 읽는다(지연 동작). 178,956,970화소를 넘으면 DecompressionBombError(예외)가 난다. 89,478,485화소를 넘으면 경고만 나는데, 경고는 try로 잡히지 않는다. 그래서 연 뒤 가로×세로를 앱이 정한 상한과 직접 비교해 넘으면 '사진이 너무 커요'를 띄운다. 4,800만 화소 아이폰 원본은 통과하게 정한다.
2. `thumbnail`로 먼저 줄인다. JPEG는 안에서 draft로 1/2·1/4·1/8 크기로 줄여 읽어 메모리를 아낀다. 크기 기준은 2장 '사진과 PDF의 API 한도'를 따른다.
3. 그다음 `ImageOps.exif_transpose`로 방향을 바로잡는다. 먼저 하면 원본 크기로 다 풀어 메모리를 많이 쓴다.
4. RGB로 바꾼다. RGBA·P·LA는 JPEG로 저장할 때 OSError가 난다. 투명 PNG는 흰 바탕에 합친 뒤 바꾼다.
5. JPEG로 한 번만 저장한다. 품질은 90 안팎(기본값 75). exif와 icc_profile을 넘기지 않으면 EXIF(위치 정보 포함)가 빠진다. JPEG 주석은 기본으로 따라가니 저장 전에 info에서 comment를 뺀다. 미리보기용으로 다시 압축한 사본을 API에 보내지 않는다.

세션에는 줄인 JPEG 바이트와 결과만 두고 원본과 PIL 객체는 버린다. HEIC는 Pillow 기본으로 열지 못하고 pillow-heif가 필요하다. MVP에서는 안내 문구로만 처리한다.

### PDF (MVP 뒤에 pypdf를 넣을 때)

- MVP에는 PDF 라이브러리를 넣지 않는다. PDF 요청이 400으로 실패하면 '암호가 걸렸거나 열 수 없는 PDF예요. 계약서 쪽만 사진으로 올려 주세요'를 띄운다.
- pypdf 6.21.4(BSD-3, 순수 파이썬)로 쪽수(`len(reader.pages)`), 암호 여부(`is_encrypted`), 글자(`extract_text`)를 본다. 스캔 PDF에서는 글자가 거의 나오지 않는다(OCR이 아니다).
- PdfReader는 만들 때 암호 PDF를 빈 비밀번호로 자동으로 풀어 본다. AES-256 방식은 cryptography 패키지가 없으면 그 자리에서 DependencyError가 날 것으로 보인다(소스로 본 판단). 그래서 PdfReader 만들기부터 try로 감싸고, DependencyError는 '암호 PDF' 안내로, 그 밖의 오류는 '열 수 없는 PDF' 안내로 보낸다. 만든 뒤 `is_encrypted`가 True면(편집 제한만 걸려도) API를 부르지 않고 안내한다. pypdf[crypto]는 넣지 않는다.
- PyMuPDF는 AGPL이라 쓰지 않는다.
- PDF 인용 대조를 넣으면, AI가 바꾼 [개인정보] 자리는 아무 글자나 맞는 것으로 보고, 양쪽의 띄어쓰기와 줄바꿈을 지운 뒤 비교한다. 글자가 거의 안 나오면 대조를 건너뛴다.

### 기준 목록 파일

- criteria.csv는 utf-8-sig로 읽는다. BOM이 있든 없든 첫 칸 이름이 어긋나지 않는다. 읽을 때마다(매 실행) 칸 이름 14개, 번호 중복, 빈 번호를 검사해 어긋나면 화면에 분명히 띄운다. 앱이 처음 켜질 때 한 번만 검사하면 나중에 고쳐 push한 파일은 검사되지 않는다.
- criteria.csv와 instructions.txt는 작으니 매 실행 읽는다. 캐시 함수나 모듈 맨 위에서 한 번만 읽게 만들면, 파일을 고쳐 push해도 옛 내용을 계속 쓴다(Streamlit은 파이썬 모듈만 감시한다). 내용이 같으면 글자도 같아서 프롬프트 캐시는 깨지지 않는다. 화면 아래 '기준 목록 n개, 버전'으로 반영을 확인하고, 그래도 옛 내용이면 Reboot한다.
- 구글 시트 'CSV로 다운로드'의 인코딩은 공식 문서로 확인하지 못했다. 실제로 받은 파일을 한 번 읽어 확인한다. 엑셀로 열어 저장하지 않는다.

### 근거와 쓰지 말 것

- 개인정보 센터 글(2026-07-01 표시): API 입력과 출력은 30일 안에 자동으로 지운다. 자동 안전 점검에 걸린 대화는 입력·출력을 최대 2년, 분류 점수를 최대 7년 보관한다. 개발자 문서는 '기본으로 보관하지 않고, 예외는 30일 보관이 필요한 Covered Models'라고 적어서, 더 보수적인 '30일 안에'로 쓴다. Opus 5.5는 Covered Models가 아니다.

- 1MB가 넘는 파일은 Streamlit 서버가 받는 동안 임시 파일을 잠깐 거친 뒤 메모리로 옮겨진다. 앱 코드는 디스크에 쓰지 않는다.

## 8장 Claude Code 킥오프 지시

코딩을 맡길 때 처음에 그대로 붙여 넣는다.

- 기준 판: Python 3.12, streamlit==1.66.1, anthropic==2.5.0, pydantic 2.x, pillow는 시험한 판. Claude API 코드를 짜기 전에 claude-api 스킬을 읽는다. 모델의 지식 기준일(2026년 6월) 뒤에 SDK 1.x·2.x 변경이 있었는데, 이 스킬의 SDK 업그레이드 안내(sdk-upgrade.md)는 0.x에서 1.x로 가는 변경만 다룬다. 그래서 1.x에서 2.0으로 오며 바뀐 것도 지킨다. MessageParam은 함수처럼 부르지 않고 사전으로 쓴다(부르면 TypeError). 클라이언트에 자격 증명을 둘 이상 주지 않는다(ValueError). models.list·retrieve에 betas를 넘기지 않는다.
- 쓰지 말 것(claude-opus-5-5 기준. 21:00에 모델을 바꾸면 thinking 설정은 2장 '21:00 모델 교체 비상안'에서 정한 설정 묶음을 따른다): temperature, top_p, top_k, 답 앞부분 미리 채우기, tool_choice any·tool, thinking 매개변수(disabled, enabled, budget_tokens, between_tools), parse의 output_format에 dict, httpx를 직접 설정하기(SDK 1.x부터 httpx2를 쓴다), parse에 stream, 요청 맨 위 cache_control(자동 캐싱), Citations.
- 쓸 것: `Anthropic(timeout=…, max_retries=0)`, `messages.create`의 `output_config`(effort와 format), `anthropic.transform_schema`, stop_reason 먼저 보기, system 마지막 블록에 cache_control ephemeral, 사진을 글보다 앞에.
- 결과 형식(Pydantic): 모든 칸 required, 기본값 없음, Field 제약(max_length, ge, pattern 등) 없음, 보기 칸은 보기 2개 이상인 한글 Literal, Optional 대신 '알 수 없음'이나 빈 글, 칸 이름에 reasoning·thinking·trace 금지, hide_input_in_errors=True.
- Streamlit: st.cache(옛), experimental 함수, use_column_width, use_container_width 금지. 너비는 width, 다시 실행은 st.rerun. 사용자 파일·결과에 st.cache_data·st.cache_resource 금지(필요하면 scope="session"). 사용자 값을 모듈 전역 변수에 두지 않는다. 값을 가진 위젯은 숨기지 말고 disabled로 막는다. 원문 인용은 st.text나 st.code로 보인다.
- 오류와 로그: except는 Exception까지만(맨 except·BaseException 금지). 예외·ValidationError 메시지를 화면과 로그에 그대로 찍지 않는다(클래스 이름, request_id, 걸린 시간만). print에는 flush=True. 배포에서 ANTHROPIC_LOG나 DEBUG 로깅을 켜지 않는다. traceback은 로컬 전용 개발 스위치가 켜졌을 때만 보인다.
- 설정 파일: .streamlit/config.toml에는 maxUploadSize, magicEnabled=false, (글꼴을 쓰면) enableStaticServing, [theme]만 넣는다. showErrorDetails는 넣지 않는다. headless와 포트는 실행 명령에 둔다. 저장소에 uv.lock과 pyproject.toml을 두지 않는다.
- 알림을 넣지 않는다. st.toast를 쓰지 않고, 캐시 함수에는 show_spinner=False를 준다.
- 킥오프 결정에 따라 바꿀 것: 위 지시는 claude-opus-5-5, 재시도 권장안(max_retries=0), 캐시 수명 5분을 전제로 한다. 대체 모델을 켜기로 했으면 `client.beta.messages.create`에 betas로 `server-side-fallback-2026-07-01`을, fallbacks로 `default`를 준다(일반 `client.messages`에는 이 인자가 없다). 재시도 방식을 다르게 정했으면 그 결정대로 max_retries와 timeout을 둔다. 캐시 수명을 1시간으로 정했으면 system 마지막 블록의 cache_control에 ttl `1h`를 준다.
